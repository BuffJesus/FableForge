FABLEFORGE · A GUIDE FOR PERODIS

Aeon Edition + Controller Support

Install Aeon Edition first. Use its intact installation as Forge's baseline. An earlier version of this guide incorrectly recommended adding the full Aeon tree over retail in Forge. That route dropped unnamed component edits and additions despite passing limited camera and level checks. Updated Forge refuses those incomplete compositions.

Forge applies the controller FMP against the already installed Aeon banks, keeping their existing record IDs and unnamed components. You do not need Chocolate Box for the controller FMP step.

Use a development build containing both the named FMP linking fix and the unnamed-component refusal. The file checks described below passed on a synthetic Aeon 5.03 baseline. They do not establish gameplay, Android, Winlator or GameNative compatibility.

The v0.18.0-rc.3 application and guide from the earlier Discord message predate these fixes. Use the corrected application supplied with this guide.

1Prepare a working Aeon installation

Start from a separate copy of Fable: The Lost Chapters (2005). For the examples below, that complete game copy is C:\FableMods\AeonGame; it contains Fable.exe and data. The downloaded Aeon extraction is a different folder, such as C:\Users\Pante\Documents\Fable\AeonEdition.

  1. Extract Aeon Edition outside the game copy. Locate the archive's existing Data folder. Keep its full contents; do not create another Data folder around it.
  2. Complete the level/WAD preparation required by Aeon's supplied installation instructions. This guide does not replace that preparation.
  3. In Windows File Explorer, open AeonEdition\Data. Copy everything inside it, then open C:\FableMods\AeonGame\data and paste. Merge folders and replace the game files when Windows asks. Keep all Aeon graphics, textures, Bones, levels and compiled definitions.
  4. Check the resulting path: C:\FableMods\AeonGame\data\CompiledDefs\game.bin. An extra data\Data or data\AeonEdition means the files were copied one folder too high.
  5. Launch this Aeon game copy using the author's normal route and verify that Aeon alone loads a game. Close it, then back up this working copy and your saves before adding controller support.

Do not add the Aeon archive or its Data folder to Forge's mod order. Its complete compiled-definition banks, graphics, textures, Bones and levels must already be installed. Choosing the game folder as the baseline is what preserves those existing components.

Level preparation for a fresh copy: Aeon's author lists FreeRoam as a requirement and points to a FreeRoam tutorial. Before pasting Aeon's Data contents, open the working copy's data\Levels\FinalAlbion.wad in FreeRoam. Select TNG and Lev (Patched), click RIP!, and choose the working copy's data folder as the destination. Close FreeRoam and rename that copy's FinalAlbion.wad to _FinalAlbion.wad. Then copy Aeon's Data contents as described above. If Aeon is already installed and working, keep its existing level setup.

Keep the WAD layout produced by the Aeon installation. Forge supports both packed and extracted levels. In an extracted installation with the WAD renamed away, Forge must not recreate FinalAlbion.wad, which would override the loose levels.

2Prepare two controller sources

Get the Controller Support legacy FMP download and its runtime DLL. The offline checks used Aeon 5.03 and Controller Support version 1. Keep the sources outside the game copy.

Controller game data

ControllerSupport.fmp

Choose this file. Forge imports its definition changes and resolves its named camera references against the Aeon baseline.

Controller runtime

FableControllerSupport/

Choose a folder named exactly FableControllerSupport containing only FableControllerSupport.dll.

No Data folder belongs inside the DLL source. The FMP supplies the game-data changes for this route. EgoCore loads the DLL during play; Forge copies it to the correct location and enables it in Mods.ini.

3Select the Aeon game folder in Forge

Extract the complete development application ZIP supplied with this guide and open FableForge.exe. Keep its companion files together. The guide-only ZIP does not contain the application.

Click Install… in Forge's top bar, or use Setup → Choose the install folder…. Select C:\FableMods\AeonGame in this example — the working game folder containing Fable.exe and data. Confirm the folder selection. This chooses Forge's baseline; it does not add a mod to the order.

Close Fable and EgoCore while Forge writes files, then open Mods. The separate AeonEdition download folder and its Data subfolder are not mod sources for this corrected recipe.

4Add the two controller layers

For the first layer, click Add a mod → Browse… → Choose mod file…, select ControllerSupport.fmp, then click Add to the order. For the second, choose Browse… → Choose mod folder…, select the DLL-only FableControllerSupport folder, then click Add to the order. The enabled order should contain exactly these two entries, from top to bottom:

  1. Controller Support FMP — ControllerSupport.fmp.
  2. Controller Support DLL — the DLL-only FableControllerSupport folder.

Keep the source files available for future rebuilds. Aeon itself is the installed baseline and has no entry in this order.

5Check and deploy

Click Check conflicts and wait. Review the report and Activity. Then click Build and deploy and wait for mods deploy: done. An error means the operation has failed; keep the existing working copy and resolve the reported issue.

If Forge reports changed or new unnamed definition entries, the enabled source cannot be safely composed against this baseline. Do not bypass that refusal: check that Aeon is already installed and absent from the source order.

Forge applies the controller definitions, installs Mods/FableControllerSupport/FableControllerSupport.dll and enables it in Mods.ini. Its Undeploy action restores the Aeon baseline that existed before this deployment.

6Load the DLL through EgoCore

Set up EgoCore using the controller author's instructions for this game copy. Forge does not supply or replace the runtime loader.

Enable Controller Support in EgoCore and launch through it. Following Aeon's supplied advice, skip an EgoCore offer to decompile the WAD. Do not install the controller's full EgoCore Data package over this FMP result. Verify that Mods/FableControllerSupport/ contains the DLL and no Data folder.

Test loading and target lock on the PC before transferring to Android. A successful file build is not a successful game launch.

7Transfer the complete prepared copy

Copy the complete game folder, including Mods, Mods.ini and EgoCore runtime files, to a separate location in the Android Windows environment you use. Keep the known working PC copy. Use the same runtime-loading route.

If it crashes, compare separate copies of the unmodified game, Aeon alone and Aeon with the controller. Record the exact crash point, executable version, Windows environment/version and available loader or crash logs.

Offline preservation checks: the updated test compares every existing Aeon definition by index, type, name and payload except the five intentional FMP imports. All 6,625 unnamed entries survive. Controller bindings change from 70 to 141, all 14 named references resolve, the DLL is unchanged, and the existing level/asset inventory is preserved. The obsolete retail-plus-Aeon composition refuses before changing prior output.
